RV32I-Alpha: a two-stage RISC-V core

RV32I-Alpha implements the 37 instructions of the RV32I base ISA, in VHDL and in SystemVerilog, with a two-stage pipeline (fetch, execute). The register of the synchronous instruction memory doubles as the pipeline register.

  • Branches are predicted not taken and cost one bubble when taken.
  • Loads take two cycles.
  • The data port accepts wait states.
  • Illegal instructions, ECALL, EBREAK and misaligned accesses or jump targets stop the core in a trap state.

The source code and the verification and implementation scripts are on GitHub (Apache-2.0).

Verification

Instruction checksriscv-formal: 37 instruction checks plus reg, pc_fwd, pc_bwd, causal, unique, liveness, ill and cover. Bounded model checking, depth 10–15 cycles.
Memory ports3 additional SymbiYosys tasks: instruction port, data port with random wait states, independent reference for illegal encodings. Depth 10–16.
Mutation testing8 bugs injected one at a time while the checks were written; each was caught by at least one check.
EquivalenceVHDL and SystemVerilog versions proven equivalent with Yosys (equiv_make / equiv_induct): 1794 / 1794 cells.
SimulationSelf-checking torture test passes in 197 cycles (GHDL).
CISimulation, formal checks and equivalence run on every push (GitHub Actions).

Bounded checks show the absence of counterexamples up to the stated depth, not correctness for all executions.

Implementation

FPGADigilent Basys 3 (Artix-7 XC7A35T), Vivado 2024.2. Core alone, out of context: 675 LUTs (44 as distributed RAM for the register file), 63 flip-flops, 100 MHz met. Full board build: 751 LUTs, 127 flip-flops, 1 BRAM; misses 100 MHz by 0.54 ns (about 95 MHz).
SKY130 (GDSII)LibreLane, sky130_fd_sc_hd: power grid, clock tree, timing repair, routing and sign-off. 0.223 mm², 13 350 standard cells. DRC (Magic, KLayout), LVS and antenna checks clean.
SKY130 timing40 MHz: setup met at the typical (+4.24 ns) and fast corners, not met at the slow corner (−4.85 ns); hold met at every corner. 5.9 mW at 40 MHz, typical corner.

Energy accounting of logic-gate neural networks

Logic-gate networks replace multiply-accumulate operations by trained two-input Boolean gates. Published comparisons usually count gates or FPGA look-up tables, and leave out the cost of getting data into and out of the network.

I built an open flow that goes from a trained model to a SKY130 netlist, places it with OpenROAD, simulates it at gate level on real test images, and derives area and energy from the recorded switching activity. It also checks that the gate-level netlist reproduces the software model bit for bit. Write-up in progress.
